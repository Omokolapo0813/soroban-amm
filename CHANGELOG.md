# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]
### Changed
- `packages/ui-components`: governance proposal statuses now mirror the nine contract lifecycle states. Abstain votes count toward turnout and snapshot-based quorum, analytics no longer invent turnout or timing data, and empty embeds show an empty state. Seed proposals are exported as `demoProposals` for examples and tests.

### Fixed
- `amm::remove_liquidity` no longer checks the pause flag, so a paused pool (admin pause or a circuit breaker trip) cannot trap LP funds (#1172). `remove_liquidity_one_sided` stays blocked while paused: it swaps against the reserves, so leaving it open would let trading continue through a pause. Swaps, deposits and flash loans are unchanged. The new `exits_allowed_when_paused()` view returns `true` to confirm that `remove_liquidity` stays open for integrators and UIs.
- `pol_vesting::create_vesting` rejects an LP token that the given `pool` does not administer, with the new `VestingError::LpTokenMismatch = 13`. A mistyped pair used to create a schedule for a token the pool never issued (#1136).
- `pol_vesting` schedules outlive the default 180-day bump. A schedule is stored with a TTL covering its `end_ledger` plus a claim window, clamped to the network maximum. Reads of a schedule refresh it and its token's committed total, and the instance is refreshed to the network maximum (#1136).
- `pol_vesting` gains a governance-gated `upgrade(governance, new_wasm_hash)` that emits `upgraded`, and `initialize` emits an `initialized` event with the stored governance and treasury addresses. The deploy module reads both back and aborts on a mismatch (#1136).
- `soroban_amm_sdk::events::decode_amm_event` returned `None` for the two most common AMM events. `swap` and `swap_exact_out` publish four fields (`swap_fot` adds the referrer as a fifth), and `flash_loan` publishes both tokens' amounts and fees. The decoder expected a five-field swap and a three-field flash loan, so an indexer built on it silently dropped every ordinary swap and every flash loan (#1149). It now accepts both swap shapes by field count and decodes the four-field flash loan.
- **Breaking (SDK only):** `FlashLoanEvent` is now `{ receiver, amount_a, amount_b, fee_a, fee_b }`. The old `{ token, amount, fee }` shape never matched an event the contract emits, so nothing decoded into it correctly.
- The `soroban_amm_sdk` test modules that were feature-gated behind a `testutils` feature nothing enables (`version_test`, `examples`) now run under `cargo test`. The orphaned `src/events_test.rs`, which used a stale API and did not compile, is removed.
- New `contracts/amm-sdk/tests/events_from_contracts.rs` deploys the real `amm` pool and decodes the events each operation publishes, so an emit-site change that the decoder does not follow fails the build. `docs/events.json` is generated from the decoder's `EVENT_SCHEMAS` table and checked by `tests/schema_json.rs` (`UPDATE_EVENTS_JSON=1` regenerates it).
- `scripts/check_test_modules.sh` (`make check-test-modules`, run in CI) fails when a `*_test.rs` file under a contract's `src/` is not declared as a `mod`, so cargo would never run it.

### Removed
- `packages/android-sdk` is removed (#962). It was one Kotlin file whose two methods, transaction building and submission, were empty TODOs, under the placeholder `com.example.amm` namespace. No workflow built or tested it, no manifest referenced it and no document mentioned it, so the directory only implied mobile support that did not exist. Removing it is deliberate: a real Android SDK would need transaction construction, signing and RPC transport, XDR fixtures shared with the Go SDK and a Gradle CI job, and should arrive as a complete package rather than a placeholder. The README now lists the client SDKs that do exist (TypeScript, Go, Rust).

### Changed
- `benches` (#1167): the baseline is now read with `serde_json` instead of a string search (which matched `amm.swap` inside `amm.swap_exact_out`), `--check` also fails when the baseline names a bench that no longer exists, and fails when a bench uses more than 60% of the 100M-instruction per-transaction limit (`--headroom-pct N` overrides it) unless `benches/allowlist.json` lists it with a reason, an issue link and a cap; the file is empty today. `--check` appends a markdown table (instructions, share of the limit, delta against the baseline) to `$GITHUB_STEP_SUMMARY`, and `--summary` prints it. New scaling benches: `batch_router.execute_batch` (2 and 4 swaps, about 10.6M instructions each, so only about nine fit in one transaction), `twap_consumer.get_twap_all` and `twal_consumer.get_twal_all` at 10 and 100 tracked pools, and `staking.stake` with 50 and 400 stakers registered (5.9M and 38.9M against 1.0M for the first staker). The parser, headroom and allowlist logic have 16 unit tests that need no contracts. Still to do from the issue: measuring every bench against WASM-registered contracts, and benches for `oracle_aggregator`, `reserve_manager.check_reserves_batch`, `token.transfer` with a full checkpoint history, `cl.swap` over more than eight ticks and `governance.vote` with maximum-depth delegation.
- `cl_position_nft` (#1162): initialization emits the configured admin and CL pool for deployment read-back verification (without requiring admin auth); admins can rotate in two steps, upgrade the WASM, and replace the CL pool for migrations. Transfers now refresh position metadata and instance TTLs alongside ownership, and approve/operator-approval writes refresh instance TTLs. `total_supply` now reports live NFTs, with `total_minted` retaining the cumulative count. Receivers can opt out of unsolicited transfers, while addresses they approved as operators may still send them NFTs. New error codes 8-11 are appended; see `docs/error-codes.md`.
- `packages/ui-components`: the three pure-logic modules under `src/lib/` (`riskAssessment.ts`, `positionValidation.ts`, `capitalEfficiency.ts`) are now the single source of truth. `RiskIndicator`, `PositionManager` and `CapitalEfficiencyCalc` import them instead of carrying private copies, so the unit tests and the coverage gate measure code that ships. `assessPositionRisk` is exported from the package root (`src/index.ts`) under its existing name, together with `validatePosition`, `computeEfficiency`, `computeEfficiencyFromTicks`, `formatEfficiency`, `isInRange`, `rangePct`, `riskLevelForScore`, `RISK_THRESHOLDS` and `INVALID_DATA_FACTOR`. New `scripts/check_reachability.mjs` (`make check-reachability`, run in CI) fails when a non-test module under a package's `src/` is not reachable from its entrypoint. **Public type changes:** `RiskLevel` gains `"unknown"`; `RiskParams` loses `volume24h` and `feeBps`, which neither implementation read; `PositionManagerProps` loses `poolVolume24h` for the same reason. `assessPositionRisk` now returns the `"unknown"` level with a `"Missing or invalid data"` factor when a metric is non-finite or negative, where it previously scored such input as healthy (`NaN` compared false against every threshold, so missing data produced a perfect score and a green indicator). `RiskIndicator` renders an explicit unknown state for that level.
- `twap_consumer` gains the production controls `twal_consumer` already has (#1159): keeper-only `add_tracked_pool` / `remove_tracked_pool` and `is_tracked`, a `MAX_TRACKED_POOLS = 100` cap enforced on implicit registration too (a rejected pool leaves storage unchanged), fault-isolated `get_twap_all_safe` and `get_twap_batch` that return a `TwapSafeEntry` per pool instead of aborting on the first bad one, two-step keeper rotation (`propose_keeper`, `accept_keeper`, `get_pending_keeper`), and a keeper-gated `upgrade`. New `TwapError` variants `TooManyTrackedPools = 17`, `NotTracked = 18`, `TooManyPools = 19`, `NoPendingKeeper = 20`, `WrongPendingKeeper = 21`; new events `initialized`, `pool_add`, `pool_remove`, `keeper_proposed`, `keeper_changed`, `upgraded`. `get_twap_all` is unchanged. `scripts/deploy/twap_consumer.sh` now aborts when `get_keeper` differs from the intended keeper (it used to log a warning and continue).
- **Breaking (ABI):** `batch_router::initialize` is now `initialize(admin, factory)`; the single-argument form is gone. `batch_router` gains an admin role (#1161): `pause`/`unpause`/`is_paused` (`execute_batch`, `simulate_batch` and `validate_batch` all return `BatchRouterError::Paused` while paused, ahead of any other check so the pre-flight never disagrees with execution), two-step admin rotation (`propose_admin`, `accept_admin`, `get_pending_admin`), `upgrade(admin, new_wasm_hash)`, and `get_admin`/`get_factory` views. New errors `NotInitialized = 12`, `Unauthorized = 13`, `NoPendingAdmin = 14`, `Paused = 15`; new events `initialized`, `pause`, `unpause`, `admin_nominated`, `admin_changed`, `upgraded`. Every public entrypoint now bumps the instance TTL, so a router used only through `simulate_batch` is no longer archived. `initialize` deliberately does not call `require_auth` (an attacker would authorize their own address, and a contract admin cannot sign for itself); `scripts/deploy/batch_router.sh` passes the admin and aborts when `get_admin`/`get_factory` read back differently from the intended addresses.
- `dex_aggregator`: the route search no longer routes back through a token it already visited. With the default `max_hops` of 4 it kept walking back and forth between tokens (`a -> b -> a -> b`), quoting a pool contract at every step, which on a three-token graph is about six quote calls to price a two-hop route. A two-hop `swap_best` costs roughly half as much (100.4M to 51.9M CPU instructions measured on the raw build). Routes that profit from passing through the same token twice are no longer found.
- `benches`: pool contracts made by the factory are now measured from their optimized WASM, which is what gets deployed, not the raw build. The raw `amm` build is over the network's 128KB contract cap and made every routing path look about 20% more expensive. `--check` and `--write-baseline` refuse to run without the optimized `amm` and `token` files (`make bench` builds them; CI already does) and `BENCH_WASM_DIR` overrides where they are read from. `benches/baseline.json` is regenerated, and `dex_aggregator.swap_best.hops_2` is back on the default 100M budget at about 41M.
- `incentive_campaigns`: `create_campaign_with_grace` (and so `create_campaign`) is now blocked while paused, as the pause policy always said. New error `Paused = 28`.
- `README.md`: Removed duplicate, hand-maintained copies of contract error codes, entrypoint signatures, and storage layout tables in favor of authoritative links to `docs/error-codes.md` and `docs/abi.json`. Streamlined the contracts overview and updated PR checklists.
- `services/graphql-api` moves to `graphql-subscriptions` 3.x, the major the graphql 17 upgrade (#984) will need, taken on its own as that issue asks. The one breaking change that applies is the rename of `PubSub.asyncIterator` to `asyncIterableIterator`, which now returns an `AsyncIterableIterator`, and the `iterall` dependency is gone. The resolvers moved into `src/resolvers.ts` so a new test can run them through a real `ApolloServer` and assert that `BAD_USER_INPUT` errors still reach clients with their `extensions.code`. Dependabot now groups `graphql-subscriptions` with `graphql` and `@apollo/server`. graphql itself stays on 16 until both libraries accept 17.
- `governance` and `factory` return a typed `NotInitialized` error instead of trapping when called before `initialize` (#931, #932). Instance configuration is read through shared accessors, so the admin setters, `propose_admin`, pool creation, `propose` and `get_params` all report `GovernanceError::NotInitialized = 35` / `FactoryError::NotInitialized = 12`. Code 2 is already taken in both enums (`InvalidVotingPeriod`, `InvalidFeeBps`), so the new variant is appended and every existing discriminant is unchanged. `governance::get_params` now returns `Result`; its success value is identical, so generated clients keep working.
- Pre-init calls and incentive-campaign failures now return typed errors instead of trapping. `dex_aggregator` (`AggregatorError::NotInitialized = 6`), `concentrated_liquidity` (`ClError::NotInitialized = 24`) and `amm` (`AmmError::NotInitialized = 21`, mirrored in `pool_interfaces` and `SdkAmmError`) report `NotInitialized` when called before `initialize`. `incentive_campaigns` gains `IncentiveError` (19 variants) in place of its `assert!`/`expect` preconditions. Existing discriminants are unchanged. A few views that used to trap now return `Result`: CL `current_tick` / `get_tokens` / `fee_bps`, AMM `get_info` / `get_fee_info` / `shares_of`, aggregator `register_cl_pool` / `remove_cl_pool`, and the incentive `get_*` lookups. Their success value is identical, so cross-contract callers and generated clients keep working. Callers using the `try_` client form see the extra error arm. See `docs/error-codes.md`.
- `soroban_amm_simulator` now builds against `rand` 0.10 and `rand_pcg` 0.10. The migration is two renames in `monte_carlo.rs`: `Rng::gen_range` became `random_range` in 0.9, and the `Rng` extension trait became `RngExt` in 0.10. The 0.10 bump does not move seeded output — the golden-value tests described in the next entry pass unchanged — so it adds nothing to the re-baseline note below.
- `soroban_amm_simulator` Monte Carlo runs are now reproducible. The generator was `SmallRng`, which `rand` documents as non-portable *and* platform-dependent — it selects Xoshiro256 on 64-bit targets and Xoshiro128 on 32-bit ones, so the same seed already produced different results on different machines, and any `rand` release was free to change the algorithm again. It is now `rand_pcg::Pcg64`, a fixed, portable algorithm, and two golden-value tests pin both the raw draw sequence and the full report for a known seed so any future drift fails the build instead of silently moving reported numbers.
- **Re-baseline stored Monte Carlo reports.** Changing the generator changes the draws, so a seeded run produces different sample statistics than it did on the previous release (the distributions are equivalent; the individual numbers move). This is a one-time shift — the point of the change is that it will not happen again unnoticed.

### Fixed
- `amm`: the emergency-withdraw guard from the M-04 audit finding (#1165) is now implemented. #1217 had merged its tests, docs and audit entry without the contract code, so `amm`, `governance` and `integration_tests` did not compile their tests. **Breaking ABI:** `emergency_withdraw(admin, to)` now takes the admin, requires a prior `announce_emergency_withdraw(admin, to)` for the same recipient, a paused pool and the emergency delay (24 h by default, up to 7 days via `initialize_with_emergency_delay`); `cancel_emergency_withdraw` clears an announcement. `set_multisig` only installs the initial guard (`MultisigGuardActive` afterwards); an active guard changes through `propose_set_multisig` / `approve_multisig_proposal` / `exec_multisig_set_multisig`. `propose_emergency_withdraw` returns a proposal id, `exec_multisig_emergency_wd(signer, proposal_id)` also waits the delay from quorum and needs a paused pool, and `get_multisig_proposal(id)` replaces the singleton. New errors `QuorumNotReached`, `InvalidQuorum`, `EmergencyDelayNotElapsed`, `InvalidRecipient`, `MultisigGuardActive`, `InvalidEmergencyDelay` (25-30). Events: `emergency_withdraw` is now `emergency_wd` with the admin in the payload; `emergency_announce`, `emergency_cancel`, `ms_set_proposed` and `ms_approved` are new and `ms_proposed` carries `(id, recipient)`. Governance `EmergencyWithdraw` proposals announce at proposal time and pause before withdrawing. `docs/pool-management-guide.md` was committed as a single base64 line and is restored.
- `governance`: `propose` had early no-op match arms that shadowed the real validation for `CreatePolVesting`, `PauseClPool`, `UnpauseClPool`, `UpdateClOracle`, `TransferAdmin` and `EmergencyWithdraw`, so none of that validation ran. `DelegationDepthExceeded` moves to error code 37 because `InvalidProposalParams` already took 36. The snapshot supply lookup uses `try_total_supply_at`.
- `soroban_amm_sdk`: the SDK's `TokenError` is renamed `SdkTokenError` (like `SdkAmmError`). Its contract spec leaked into every wasm that links the crate, so `token.wasm` carried two `TokenError` enums and `amm_fuzz`'s `contractimport!` could not compile. Codes are unchanged. `governance` imports it under the old name.
- `twap_consumer`: `get_twap_price` / `get_twap_both` read the pool before looking at snapshot history, and `get_cl_twap` uses `try_observe`, so a pool that does not implement the oracle interface returns `CrossContractCallFailed` instead of `InsufficientHistory` or trapping (#964). The test CL pool mock gained `observe`.
- `token`: the `total_supply_at` tests used a `Result` return and the pre-SDK-21 `ledger().set(seq, ts)`; they now compile and the checkpoint-truncation test lifts the test budget.
- `staking`: the event tests compared raw `Val` payloads, which never match for symbols longer than nine characters, so they could not find `initialized` or `admin_nominated`. The four "cost does not grow with staker count" tests compared CPU instruction counts, which in the native test host scale with the size of the whole test ledger even for a plain SAC transfer; they now count the ledger entries a call changes, which is what the O(1) registry guarantees.
- `go-sdk` and `packages/sdk`: `AmmError` tables extended to codes 22-30. `packages/sdk` tests are ported to the stellar-sdk 17 XDR object model and `invoke.ts` hashes with `Buffer.from(signed.hash())`.
- `scripts/check_branch_protection_doc.mjs` is added (#1218 merged the Makefile targets and the doc without it). The `npm-packages` job now has an explicit name so its required context is `npm-packages (<dir>)`; GitHub's default would have included the test command. `BRANCH_PROTECTION.md` lists `event-schemas`, and CI runs the check and its tests.
- `services/health-dashboard`: tests updated for the min/max price-range bars, the zero-baselined axis label and the table built from DOM nodes. `services/webhook-streamer`: `token` SEP-41 schema entries gained their `version`, and the oracle_aggregator, factory and router schemas match the code. `docs/error-codes.md` covers `TwapError` 15-16, `FactoryError` 13-15, `AdapterError` and `SdkTokenError`.
- `services/webhook-streamer`: event fields were named from a table keyed by event name alone, so a concentrated-liquidity `swap` got AMM field names while AMM `swap` and `flash_loan` events were unnamed (#1124). Schemas now live in `src/event-schemas.json`, keyed by contract kind, event name, schema version and payload arity, and cover every event the 18 contracts emit. Set `CONTRACT_KINDS=<contractId>:<kind>` so each watched contract gets its own schema; events from a contract with no kind, or with a payload that does not match exactly, keep the generic `{ "value": [...] }` shape instead of guessed names. `PoolEvent` gains `contractKind`. `scripts/check_event_schemas.mjs` runs in CI and fails when a contract emit site and the schema file disagree, and generates the field catalogue in `docs/event-schema-versioning.md`. **Behaviour change:** without `CONTRACT_KINDS`, payloads that used to be named are now generic.
- `services/webhook-streamer`: subscriptions, dead letters and poller cursors were kept in memory, so a restart dropped every registration and failed delivery and re-read from `START_LEDGER` (#1125). Set `DATA_DIR` and the service keeps them in `state.json`, replaced atomically on every change. The poller saves a contract's cursor only after its events were dispatched, so delivery is at least once and a crash replays a page instead of skipping it; every delivery carries `X-Webhook-Id` (the event id) for deduplication. When RPC no longer retains the saved cursor or `START_LEDGER`, the poller resumes from the oldest retained ledger and reports the gap in its log and in `/health` under `poller.gaps`, instead of failing the same request forever. SIGTERM and SIGINT stop the poller, drain in-flight deliveries (up to `SHUTDOWN_TIMEOUT_MS`), flush state and exit 0.
- `services/webhook-streamer`: the management API had no authentication, listed every subscriber secret, and sent the secret itself as the delivery auth header (#1123). Every route except a minimal `GET /health` now needs `Authorization: Bearer $MANAGEMENT_API_TOKEN` (compared in constant time), and the service refuses to start without a token unless `MANAGEMENT_API_INSECURE=true`. Secrets are never returned or logged: subscriptions and dead letters expose `hasSecret` instead. Deliveries are signed with `X-Webhook-Signature: t=<unix>,v1=<hmac-sha256>` and carry `X-Webhook-Id`; the raw `X-Webhook-Secret` header is gone unless `WEBHOOK_LEGACY_SECRET_HEADER=true` (for one release). Request bodies are capped at 64 KiB (`413`), and bad input gets distinct `400` messages for invalid JSON and invalid fields. **Breaking for receivers:** verify the signature, see the README for the algorithm and migration steps.
- `services/graphql-api`: every ingested event and price point was deleted on arrival (#1126). `RpcIngester` stamps events in seconds, but `PoolIndexer` pruned, windowed and aged data against `Date.now()` in milliseconds, so `poolEvents`, `priceHistory` and `twal` came back empty with real data. The whole service now uses seconds since the Unix epoch: timestamps are typed as `Seconds` (`src/time.ts`), the indexer takes an injectable clock, and `HealthAlert.firedAt` and the `priceHistory` `from`/`to` arguments are seconds too. Clients that passed millisecond values to `priceHistory` must switch to seconds.
- `@soroban-amm/sdk`: three transaction builders had the wrong arity and four reads targeted entrypoints the contracts do not export (#1047). `cl.mintPositionParams` now takes the trailing `deadline: u64` (8 args, was 7), `token.approveParams` takes `liveUntilLedger: u32` (4, was 3), and `factory.createPoolParams` leads with `caller` and takes `feeTier` (5, was 4), with a new `createPoolWithFeeBpsParams`; `Option<BytesN<32>>` arguments are now encoded as `None` → void / `Some` → a one-element bytes vector. `AmmPool.getFlashLoanFeeBps` reads `get_info().flash_loan_fee_bps` instead of a non-exported `get_flash_loan_fee_bps`, `AmmPool.getName` is removed (the AMM contract has no `get_name`), `FactoryClient.poolCount` calls the exported `get_pool_count`, and `cl.observe(secondsAgo)` mirrors `observe(u64) -> i64` with a new `observeBatch` for multi-point sampling. `AmmPool.simulateSwap` now calls the contract's `simulate_swap` and decodes its `SwapSimulation` verbatim (now carrying `effectivePrice`/`spotPrice`) instead of approximating the result from reserves. `abi.test.ts` is rewritten to be driven by a generated `src/__fixtures__/contract-abi.json` oracle: every builder's arity, order and XDR types, and every method name the clients send, are checked against the contract sources. `npm run generate:abi` regenerates the fixture and `npm run check:abi` fails on any diff.
- `batch_router`: `simulate_batch`/`validate_batch` rejected every batch containing a concentrated-liquidity swap, because the simulator gated every op on the AMM-only `factory.get_pool_tokens`, and disagreed with `execute_batch` on AMM edge cases (#1043). The pool-kind check and amount validation now live in one `validate_op`/`validate_pool` path shared by `execute_op` and `simulate_op`, so both accept exactly the same batches; CL swaps are quoted through the pool's `estimate_price_impact`. The simulator now mirrors the pool exactly: it applies the net-of-protocol-fee reserve credit and chains it across ops in a batch, reports first-deposit shares as `isqrt(a*b) - MINIMUM_LIQUIDITY` (rejecting a first deposit that would mint no more than the locked 1 000 shares) so a `min_shares` inside that gap fails as `SlippageExceeded`, mirrors `amm::swap`'s output-reserve guard, and rejects paused AMM and CL pools. New typed errors `PoolPaused` (8), `UnsimulatableChain` (9), `InsufficientLiquidity` (10) and `InsufficientShares` (11) surface these conditions instead of raw pool errors or silently wrong quotes; a second CL op on a pool an earlier op touched is refused as `UnsimulatableChain`. `AmmPoolInterface` and `ConcentratedLiquidityInterface` gain an `is_paused` view. New tests assert `simulate_batch` equals `execute_batch` across nine batch shapes and cover every returnable error variant, and `docs/error-codes.md` documents the new codes.
- `staking`: `RewardPoolBalance` was decremented twice per reward — once when `update_rewards` distributed it and again when `claim`/`unstake`/settlement paid it out (#1045). After the first payout the counter went negative, `update_rewards` clamped to it and distributed nothing, and every reward cycle after the first was stranded in the contract; `get_pool_info` also reported a negative balance and the reward-pool cap compared against the corrupted value. The counter is now split into undistributed rewards (funded by `add_rewards`, debited only by `update_rewards`, and what the cap and `reward_pool_balance` report) and owed rewards (new `OwedRewards` storage, credited by `update_rewards`, debited by exactly what claims and settlements pay, forfeited by `emergency_withdraw`). A new `get_owed_rewards` view exposes the owed amount, and a new admin-only, paginated `reconcile_reward_accounting` repairs already-deployed contracts by recomputing both counters from the reward-token balance and the staker index, emitting a versioned `rewards_reconciled` event. `PoolInfo` is unchanged for ABI compatibility; no error variants changed.
- `twap_consumer` / `twal_consumer`: `save_snapshot` and `save_cl_snapshot` trapped on every real network (#985). Snapshots were stored under `Snapshot(pool, ledger_timestamp)` / `LiquiditySnapshot(pool, ledger_timestamp)`, but a transaction's footprint is fixed at simulation against an earlier ledger, so the key written at apply time was never in the footprint. Reads had the same flaw, since the snapshot they loaded was picked by the current timestamp. Each pool's snapshots now live in one sorted `Snapshots(pool)` entry, so no key depends on the ledger clock, and a concurrent save between simulation and apply changes only values, not the footprint. Readers binary-search the same list; `delete_snapshot`, pruning and the same-ledger overwrite follow it; read results are unchanged for the same history. Because the whole history is one ledger entry, retention is capped at `MAX_SNAPSHOTS_PER_POOL = 512` per pool (the oldest is dropped past it; about 39 KiB for TWAP and 28 KiB for TWAL, under the 64 KiB entry limit). `twap_consumer::set_retention_policy` rejects a larger `max_snapshots_per_pool`, and `twal_consumer` gains `get_snapshot_count`. No migration is needed: every save has trapped on live networks, so no `Snapshot(pool, ts)` entries exist there. `scripts/check_storage_keys.sh` (`make check-storage-keys`, run in CI) fails if a key in either contract is built from the ledger timestamp or sequence, and the new `twap` e2e flow saves snapshots through simulate-then-submit and reads a 60-second TWAP and TWAL on testnet.
- `governance::vote` always trapped outside tests: it locks LP tokens through `LpToken::lock`, which needs the token's locker to authorise, and no production path ever made governance the locker (#986). The LP token starts with the pool as locker, and only the pool (the token's admin) can change it. New admin-gated `amm::set_lp_locker(locker)` lets the pool admin delegate it, and new `governance::claim_lp_locker()` has governance make that call itself when it is the pool admin. `factory::create_pool` calls it whenever it deploys governance. `scripts/deploy/governance.sh` wires the locker through the pool (or governance), reads it back, and exits non-zero if it is not governance, instead of warning and continuing. The e2e governance flow does the same and now also asserts the lock and the unlock. A new integration test (`governance_locker_test.rs`) runs create_pool, propose, vote, execute and unlock_vote with explicit per-call auths and no `mock_all_auths`.
- `v2_to_v3_migration` now calls the real concentrated-liquidity interface and mints the position directly for the LP, so migrated liquidity remains under the LP's control. Reversed token pairs are mapped into V3 order, automatic ranges are aligned to the pool's tick spacing and clamped to usable CL bounds, and explicit misaligned ranges fail before V2 funds move. Integration coverage now uses the real AMM, concentrated-liquidity, and position-NFT contracts instead of a mock V3 pool.
- The Docker image and the release workflow pinned Stellar CLI releases whose locked dependency tree no longer compiles on the pinned Rust 1.98.1. `cargo install stellar-cli --locked` builds the CLI's own `Cargo.lock`, and 25.1.0 (Dockerfile) and 23.0.0 (`release.yml`) lock `ethnum` 1.5.2 and 1.5.0, which fail with `E0512: cannot transmute between types of different sizes`. That failed the `docker-build` CI job on every commit since it was added (#1017), and would have failed the next tagged release at "Install Stellar CLI". Both now use 27.1.0, the version `smoke-test.yml` already uses: the Docker image builds it from source (it locks `ethnum` 1.5.3) and also installs `libdbus-1-dev` and `libudev-dev`, which 27.x needs on Linux, and `release.yml` installs it with the `stellar/stellar-cli` action as `smoke-test.yml` does instead of compiling it. `README.md` lists the same version. With the CLI building, `docker-build` then reached the Dockerfile's dependency-caching `cargo fetch`, which had never run: it copies only the member manifests, and Cargo will not load a manifest whose targets have no source file. That step now creates empty placeholders for each member's targets, fetches, and deletes them in the same layer.
- `soroban_amm_simulator`: the concentrated-liquidity module had no swap engine, and `ClPoolState::current_tick` was hardcoded to 0 by `initialize` whatever the price (#961). `ClPoolState::swap` now ports the contract's tick walk step for step (tick crossing with `liquidity_net`, fee growth and `fee_growth_outside` flips, protocol fee split, price limits, partial fills), `initialize` derives the tick from the price, and a new `initialize_at_tick` mirrors the contract's `initialize`. `tests/cl_swap_parity.rs` runs the real contract beside the simulator on shared fixtures and requires exact agreement after every swap. The sqrt price and current tick are now private (read them with `sqrt_price_x96()` / `current_tick()`) so they can no longer be set out of step with each other, `cl::math::sqrt_price_x96_to_tick` now returns the floor tick as the contract does instead of rounding up between ticks, `ClPoolState::new` rejects `fee_bps = 10_000` as the contract does, and the placeholder `initialize_tick`, which created tick entries the contract can never hold, is removed.
- `concentrated_liquidity`: the position path (mint, single-token mint and its
  quote, `modify_position`, burn, `quote_position`) converted between liquidity
  and token amounts through `mul_u128_u96`, which silently dropped every bit of
  its product above 128. `overflow-checks` did not catch it because the loss
  happened in a `wrapping_shl`. Sqrt-price differences grow exponentially with
  tick magnitude, so ordinary ranges overflowed: for L = 1e6 over
  [100_000, 200_000] the true product is 5.09x `u128::MAX` and the result came
  back 55.7x too small, and a 10^12 deposit there was credited ~1e6 liquidity
  instead of ~1.5e14. `get_amount0_delta`, `get_amount1_delta`,
  `get_liquidity_for_amount0` and `get_liquidity_for_amount1` are now evaluated
  over 256-bit intermediates through the existing `mul_div` and
  `amount{0,1}_delta_exact` helpers, keep rounding down (toward the pool), and
  return `None` instead of a wrapped value when a result cannot be represented.
  The contract reports that as the new `ClError::MathOverflow = 25` (mirrored
  in `pool_interfaces`). `mul_u128_u96` is removed. `amm-fuzz` now checks all
  four conversions against an arbitrary-precision reference (#963).
- `twap_consumer`: `get_twap_all` trapped for the whole tracked set once any
  concentrated-liquidity pool was registered. `save_snapshot` and
  `save_cl_snapshot` pushed into one untyped list and `get_twap_all` read every
  entry through the AMM-only `get_price_cumulative`, which a CL pool does not
  implement. Tracked pools now carry a `PoolType` (`Amm` / `Cl`), mirroring
  `twal_consumer`, and `get_twap_all` dispatches per entry to `get_twap_price`
  or `get_cl_twap`. It returns `Vec<TwapEntry>` (`pool`, `pool_type`, `twap`)
  instead of `Vec<(Address, i128)>`, because the two paths report different
  quantities: a price for `Amm`, a mean tick (widened from `i64`) for `Cl`.
  `get_tracked_pools` keeps its signature; `get_tracked_pools_typed` adds the
  types. A pool that does not implement the interface its type implies, or is
  not a contract, now returns the new `TwapError::CrossContractCallFailed = 14`
  instead of a host trap, on every snapshot and TWAP read.
  **Migration:** the typed list is stored under a new key. Until it is first
  written, the legacy untyped list is read with every entry typed `Amm`, which
  is how it was read before. The first change to the tracked set (a new pool,
  or a re-typed one) writes the typed list and deletes the legacy key. A
  legacy entry that is really a CL pool is re-typed `Cl` by the keeper's next
  `save_cl_snapshot` for it; until then `get_twap_all` returns
  `CrossContractCallFailed` for it rather than trapping (#964).
- `@types/node` matches the Node 22 runtime CI uses. `packages/sdk`,
  `services/graphql-api` and `services/webhook-streamer` type-checked against
  Node 26 typings, so `tsc` accepted APIs that do not exist on Node 22; all
  three are on `^22.20.4` now (webhook-streamer's exact `26.5.0` pin came from
  a Dependabot bump and is replaced by a caret range like the others). `.nvmrc`
  is the single source of the CI Node major, `setup-node` reads it, every

  `node-versions` CI job (`make check-node-versions`) fails when any package's
  `@types/node` or `engines.node` disagrees with it (#983).
- `@soroban-amm/sdk`: `AmmErrors` / `AmmErrorNames` stopped at code 18, so `decodeError` fell through to a generic error for `AlreadyExecuted` (19), `ProposalExpired` (20) and the new `NotInitialized` (21). All three are now mapped, and a test parses `pub enum AmmError` from `contracts/amm/src/lib.rs` so the TypeScript map can't fall behind the contract again unnoticed.
- `incentive_campaigns`: `recover_leftover_funds` could run more than once on the same campaign. Recovery marks the campaign inactive but leaves `funding_amount - total_distributed` unchanged, so every repeat call transferred the same leftover again, taken from the balance other campaigns hold in the same reward token. A campaign that is already inactive now returns `IncentiveError::CampaignInactive`.
- `concentrated_liquidity`: the swap engine priced every step in a
  3-significant-digit scale (`p_c = (sqrt_price_x96 * 1000) >> 96`) while
  minting, burning and quoting priced at the full `sqrt_price_x96`. One unit of
  that scale is a ~20-tick move, so any trade large enough to change it at all
  moved the pool ~20 ticks regardless of size — a 3,900-token swap against
  L = 5e8 moved the price 20 ticks where the correct answer is a fraction of
  one. The pool price therefore ran away from the price its trades had actually
  paid for and crossed out of live position ranges without the volume to
  justify it. Positions then redeemed against a price the pool had never been
  at: in the reproducer all three positions were valued entirely in token A,
  leaving the pool holding `(a = 0, b = 400225)` against `tokens_owed`
  `(a = 400508, b = 0)` — solvent in aggregate, insolvent per token, with token
  B stranded and unclaimable. `compute_step`, `compute_final_price_and_output`
  and `compute_final_price_and_input` now work entirely in Q64.96 using the
  canonical Uniswap V3 formulas, evaluated through a new 256-bit-intermediate
  `mul_div`/`mul_div_ceil` so products like `liquidity * sqrt_price` no longer
  have to fit in a `u128`. Input rounds up and output rounds down, so a step can
  never move the price further, or pay out more, than the input justifies.
- `concentrated_liquidity`: `amounts_for_liquidity_to_burn` and
  `liquidity_from_amounts` valued in-range positions at
  `tick_to_sqrt_price_x96(current_tick)` — the price at the tick's lower edge —
  rather than the pool's live `SqrtPriceX96`. A tick spans a whole price band
  and every swap moves the price inside it, so an in-range position was split
  between the two tokens at a price the pool was not at, redeeming for more of
  one token than the pool held. This was the residual per-token shortfall left
  after the swap-price fix above (171 units on ~400,000 in the reproducer).
  Both now take the live price, clamped into the position's own band.
- `concentrated_liquidity`: `initialize` never wrote `SqrtPriceX96` — only
  swaps did — so an untraded pool had no stored price and every reader had to
  reconstruct one from the tick. It is now set at initialization; readers keep
  a tick-derived fallback so pools deployed before this change still work.
- `amm-fuzz`: the CL stateful suite now asserts per-token solvency on every
  step (the pool's balances cover every position's burn proceeds plus its
  uncollected fees). The four regression tests that documented the bugs above
  — `cl_burn_all_returns_everything`, `cl_solvency_per_token_regression`,
  `cl_solvency_total_value_regression` and `cl_active_liquidity_regression` —
  were `#[ignore]`d as known failures and now run as ordinary tests.
- CI has been red on `main` since 2026-08-30. The WASM build pulled the off-chain `soroban_amm_simulator` CLI into `cargo build --workspace --target wasm32v1-none`, where its host-only dependencies (clap, csv, rand/getrandom) cannot compile — breaking `build-and-test`, `fuzz` and `release.yml` alike. Which crates are excluded now lives in a single `scripts/build_workspace.sh`, shared by `ci.yml`, `release.yml`, the `Makefile`, `deploy.sh` and `optimize_contracts.sh` (the last two carried the same latent bug), so the five cannot drift apart again.
- The `Makefile` was corrupted by 5529cc1: literal `\t` sequences in place of tabs made it unparseable (`Makefile:37: *** missing separator`), which is why the `fuzz` job died two seconds in. The same commit renamed the target to `fzzz-cl` and broke `MAKEFILE_LIST`, `RUSTDOCFLAGS`, the `*.wasm` glob, and the `optimize`/`audit` recipes. Restored, keeping the intended `release-build` alias.
- `release.yml` was corrupted by the same PR: a step truncated mid-command with a literal `\n` swallowed the `Generate checksums` and `Update changelog` steps, so the workflow failed to parse and every tag push failed instantly. Restored, and given `fetch-depth: 0` since the changelog walks tag history.
- `soroban_amm_simulator` could never load a trade file in JSON. `TradeRecord` deserialized a `#[serde(flatten)]` internally tagged `TradeAction`, and both `flatten` and `tag = "..."` route the value through serde's private `Content` buffer, which rejects 128-bit integers ("i128 is not supported", serde-rs/serde#1183). Deserialization now goes through an explicit flat struct that preserves the documented on-disk format, shared with the CSV loader so both formats keep one `kind` mapping. Covered by a new serialize/load round-trip test.
- The simulator's `cl::math::tick_to_sqrt_price_x96` was a stub that applied only tick bits `0x1` and `0x2`, returning price 1.0 for every other tick and making the CL simulator's output meaningless. Replaced with the full binary-decomposition algorithm ported from `contracts/concentrated_liquidity`, verified to agree bit-for-bit with the on-chain function.
- `soroban_amm_sdk::decode_amm_event` could panic on malformed event data instead of returning `None`: the SDK's tuple `TryFromVal` unpacks through the host's `vec_unpack_to_slice`, which traps on an arity mismatch rather than returning an error, so `.ok()?` never got a chance. All decode branches now check the payload length first, keeping the function total for untrusted RPC input.
- `scripts/size_report.sh` used GNU-only `realpath --relative-to`, aborting the whole script (and `make size`/`make size-check`) on macOS.
- propose_emergency_withdraw: expiry timestamp is now refreshed only when a new approval is recorded, preventing a single signer from keeping a stale proposal alive indefinitely.
- concentrated_liquidity::set_position_nft: changing the NFT contract address now requires the pool to have no tokenized positions, preventing index orphaning and unauthorized control transfer.
- `LpToken::unlock` previously authorised against the currently configured `DataKey::Locker`, so any `set_locker` rotation orphaned LP tokens whose locker had locked them via `LockedVote`. The unlock function now requires auth from the locker that originally locked the tokens, recorded per-locker in a new `LockEntry(Address, Address)` storage entry. Each locker retains authority over its own contribution; a freshly-set locker can only unlock tokens it itself locked. (closes #556)
- `contracts/router/Cargo.toml` and the workspace `Cargo.toml` both contained duplicate table entries (`[dependencies]`, `[dev-dependencies]`, and member list) that caused `cargo` to refuse to load the workspace entirely. Merged into single tables and removed duplicate members.
- `concentrated_liquidity`: two compounding bugs let `current_tick` desync from the discrete `active_liquidity`/`fee_growth_outside` bookkeeping after a swap. First, the tick-crossing target price was derived via a crude reimplementation (`sqrt(tick_to_price(tick))` rescaled) instead of the existing high-precision `tick_to_sqrt_price_x96`, losing enough precision to round-trip to the wrong tick; fixed by reusing `tick_to_sqrt_price_x96` at all 3 call sites. Second, a swap step that stays *within* the current range (not crossing) computes its landing price in the engine's deliberately low-precision (~3 significant digit), pool-favorable-rounded scale, which right at a boundary can be indistinguishable from (or past) the next tick once reconstructed at full precision — resolving `current_tick` past a boundary the discrete bookkeeping never actually crossed. Fixed by clamping that branch's `current_tick` to the known-correct side of the boundary it was told not to reach. Together these caused `active_liquidity()` to diverge from the true sum of in-range positions after a multi-tick swap, and caused positions to lose previously-accrued fees once price crossed out of their range. The originally-suspected nearest-vs-floor rounding difference between `price_to_tick` and `sqrt_price_x96_to_tick` was real but not itself sufficient to reproduce the bug; `price_to_tick` is still removed as a genuine (if secondary) inconsistency. (closes #786, closes #785)
- `concentrated_liquidity`: `burn_position`/`burn_position_by_token_id`/`collect_fees` recomputed principal and fee payouts independently of the swap engine's own (lower-precision) price-stepping math, so a payout could exceed the contract's actual token balance and hard-trap instead of failing gracefully. Burn and fee-collection payouts are now clamped to the contract's real on-hand balance at transfer time, with any shortfall preserved in the position's `tokens_owed` so it remains claimable once the contract's balance recovers, instead of being lost. (closes #787)
- CI installed JavaScript dependencies with `npm install`, which re-resolves the tree on every run and rewrites lockfiles as it sees fit, so a transitive dependency publishing between two runs could turn CI red on an unchanged tree — the exact failure `rust-toolchain.toml` was introduced to eliminate on the Rust side. Three of the seven npm workspaces (`packages/ts-advanced-client`, `services/graphql-api`, `services/health-dashboard`) had no `package-lock.json` at all, so there was no record of what had actually been installed: a supply-chain gap, and most acutely for the deployed `graphql-api` service. All three now commit a lockfile, and `ci.yml` installs with `npm ci`, which installs exactly what the lockfile pins and fails if it disagrees with `package.json`, making lockfile drift visible instead of silent. All seven workspaces were verified to build and pass their CI test command against `npm ci` on Node 22, the same runtime `ci.yml` uses. Dependabot already watches all seven manifests, so pinning does not mean going stale. (closes #956)
- `@soroban-amm/sdk`: the `GovernanceClient` modelled a contract that does not exist. It called 13 entrypoints absent from `contracts/governance` (`get_voter_count`, `list_voters`, `get_delegators`, ...), and mis-encoded three arguments: `vote` and `propose` sent their enums as a bare symbol/string instead of the `#[contracttype]` variant `scvVec([scvSymbol(name), ...payload])`, and `unlock_vote` passed `(proposal_id, voter)` where the contract takes `(voter, proposal_id)` (`contracts/governance/src/lib.rs:1090`), so every transaction those three methods built would have failed. The client now exposes only the real governance entrypoints, plus clearly-documented client-side compositions that page or fan out over them; encodes every governance enum as a contract-type variant; orders the `unlock_vote` arguments as the contract expects; models `ProposalData` (the 17-field `Proposal` struct, which has no `status`) and derives `Proposal.status` separately; covers all 18 `ProposalKind` variants; and decodes the 35 `GovernanceError` discriminants into a typed error. A new `governance.test.ts` parses the Rust source so the entrypoint allowlist and the enum/struct shapes cannot fall behind the contract again, and pins the `unlock_vote(voter, proposal_id)` regression. (#1046)

### Added
- `router` and `dex_aggregator` gain an admin pause switch: `pause(admin)`, `unpause(admin)` and `is_paused()` (#937, #938). Both check that `admin` is the stored admin (`Unauthorized` otherwise) and require its authorization, and emit versioned `pause` / `unpause` events carrying `(admin,)`. While paused, router `swap_exact_in` / `swap_exact_out` return `RouterError::Paused = 9`, and aggregator `set_max_hops`, `register_cl_pool`, `set_routing_tokens`, `remove_cl_pool`, `execute_route` and `swap_best` return `AggregatorError::Paused = 7`. Quotes and path views stay callable. New codes: `RouterError::Unauthorized = 10`, `AggregatorError::Unauthorized = 8`.
- `LpToken::migrate_legacy_lock(holder, locker, amount)` admin-only helper to migrate a holder's pre-fix `Locked(holder) > 0` balance into per-locker `LockEntry` entries after upgrading from a contract version that tracked only the total `Locked` counter.
- `LpTokenInterface::unlock` now takes an explicit `locker: Address` parameter; `governance::unlock_vote` calls it with `env.current_contract_address()` as the locker.
- `batch_auction`: settlement venues are now validated against a registry instead of trusting a pool's self-reported token pair, closing a fund-drain vector where an order could name an arbitrary attacker-controlled contract as its venue. A venue is accepted only if the admin has explicitly allow-listed it (`add_venue`/`remove_venue`/`is_venue_allowed`/`list_venues`) or the configured factory (`set_factory`) attests to it having deployed that pool for that token pair (using a new `concentrated_liquidity::fee_bps()` getter for CL venues). Venues are re-validated at settlement, not just submission, so one removed in between causes that order to be refunded instead of executed. Also adds a `MAX_ORDER_LIFETIME_SECS` ceiling on trader-supplied deadlines, a permissionless `expire_order`/`get_expired_orders` path so a trader isn't dependent on the full batch window elapsing to reclaim an expired order, and `claim_refund` so a refund/payout whose transfer fails at settlement becomes claimable later instead of being permanently stranded. (closes #700)

### Breaking
- `v2_to_v3_migration::migrate` replaces `min_v3_shares` with `min_deposit_a` and `min_deposit_b` in V3 token order. `MigrationResult` now reports deposited and leftover amounts, final ticks, and an optional position NFT token ID instead of synthetic V3 shares.
- `LpToken::unlock(holder, amount)` is replaced by `LpToken::unlock(holder, locker, amount)`. The previous locker parameter read from `DataKey::Locker` storage is now an explicit argument. External SDK clients bound to the old public ABI must switch to the new signature.
